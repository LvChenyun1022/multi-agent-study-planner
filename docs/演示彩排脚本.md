# ExamOS 决赛演示彩排脚本

场景数据：`python scripts/seed_demo.py` 生成（基于真实课表，见文末说明）。
启动：`.venv/Scripts/python -m streamlit run examos_app.py`

## 演示弧线（约 5 分钟）

### 第 1 幕：建档与风险感知（1 分钟）

1. 打开「课程与考试」页，展示四门已建档课程：
   中级微观经济学（12/28）、离散数学（12/30）、
   中级宏观经济学（12/31）、商务统计学（2027/1/4）。
2. 讲解点：每门课的知识点权重、任务工时与依赖均经
   CourseSpec 同源校验；掌握度标注为自评，未冒充测验证据。
3. （可选）现场演示 scope_text 智能解析：粘贴一段考试范围文字，
   LLM 抽取结果标注【待确认】，日期换算由确定性代码完成。

### 第 2 幕：生成计划（1 分钟）

4. 打开「复习计划」页，展示每日时间预算：
   Day 0（周五）只有 3h——因为课表显示周五白天还有
   室内高尔夫与习概课；考试周起每天 8h。
   **讲解点：系统不猜测空闲时间，时间预算由学生按真实约束给出。**
5. 点击「生成初始复习计划」。展示：
   - 风险评分表：微观 R≈0.61 最高（4 学分学位课 + 倒计时 3 天）；
   - Day 0 的 3 小时全部排给微观；
   - 预警区：微观「历年卷模拟一」2h 无法排入——
     **讲解点：时间不足时系统诚实报告失分风险敞口，而不是假装能排完。**

### 第 3 幕：执行反馈与动态重规划（2 分钟）

6. 打开「执行反馈」页，Day 0 全部 100% 提交：
   监控判定「无显著偏差，继续执行当前计划」——
   **讲解点：显著性闸门，小偏差不折腾计划。**
7. 点击「进入下一执行日」。Day 1 把「离散数学」完成率拉到 25%，
   其余保持 100%，提交：
   - 监控判定「单日偏差 75% 超过阈值 40%」，触发重规划；
   - v2 中离散数学在 Day 2–3 获得 6h+ 的倾斜分配；
   - 展示 v1/v2 差异表与守恒校验「通过」。
8. （加分项）立即再把离散拉到 25% 提交一次：
   同一课程 24h 冷却期内不再重复触发，判定为「冷却期内抑制」——
   **讲解点：防止计划抖动；学生手动请求可绕过冷却。**

### 第 4 幕：诊断与画像（1 分钟）

9. 打开「诊断与画像」页，对离散数学运行诊断 Agent
   （RAG 检索 + 致远一号生成报告，约 1–2 分钟，可跳过）。
10. 修改「图论」掌握度 0.45 → 0.30（模拟一次测验后发现更薄弱），
    保存；回到「执行反馈」页提交下一次打卡时，
    「掌握度变化」信号会参与重规划判定。

## 评委可能提问与应答要点

| 提问 | 应答 |
| --- | --- |
| 为什么不用强化学习？ | 复习排程是可解释的资源分配问题，确定性贪心 + 边际收益递减有明确语义；每个数字都能向学生解释来源，且 141 项测试可复现。 |
| 掌握度从哪来？ | 目前是自评/中性先验（页面如实标注）；2.0 画像引擎已支持测验证据加权更新，未完成计划绝不降低掌握度。 |
| 每天可用时间怎么来？ | 学生按课表显式给出（本演示按真实课表推算）；系统自动推导空闲时间属于明确不做的边界——猜错了比没有更糟。 |
| 数据安全？ | 状态本地 JSON 存储；LLM 调用经学校致远一号，数据不出校。 |

## 场景数据说明

- 课程、学分、上课时间来自 2026-2027-1 学期真实课表；
- 考试日期为演示设定（原型阶段未接入教务系统）；
- 掌握度为自评演示值，未经真实测验证据校准；
- 每日可用时间按课表推算：周五白天有课 → 3h；考试周 → 8h。
